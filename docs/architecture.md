# Architecture for contributors

The server is one Go binary. It owns users, libraries, works and their source matches, chapters, downloads and the job queue, and serves the REST API the web app and other clients use. Metadata comes from the separate metadata service; sources come from out-of-process source plugins.

```
cmd/panelarr/            entry point: serve, migrate, healthcheck, version
api/openapi.yaml         the public API contract (spec-first)
internal/api/            HTTP layer: router, middleware, problem errors, handlers
internal/api/apigen/     code generated from the spec (do not edit)
internal/auth/           sessions, API keys, password hashing, login limits
internal/users/          accounts, grants, invites, first-run setup
internal/secret/         encryption of stored secrets
internal/meta/           the metadata service: connection, checks, catalogue
internal/meta/metatest/  a fake metadata service for tests
internal/imagecache/     fetched images (covers) cached on disk; signed image links
internal/plugins/        source plugins: registration, sync, config, visibility, browsing
internal/plugins/pluginstest/  serves made-up plugins over gRPC for tests
internal/queue/          the task queue (claim, lease, retry, caps, cancel, pause)
internal/jobs/           named background jobs and their runs
internal/limits/         per-source concurrency and rate limits
internal/events/         the event hub behind the event stream
internal/library/        works, libraries and matching works to source series
internal/chapters/       unified chapters, chosen copies, update checks
internal/reader/         pages, progress, history, reader settings and preferences
internal/storage/        storage backends (local, S3) and their configuration
internal/cbz/            CBZ archives with ComicInfo.xml
internal/downloads/      the download task, naming, auto-download, moving files
internal/textmatch/      title and name normalization and similarity
internal/config/         startup settings from env and flags
internal/logging/        structured logs
internal/metrics/        Prometheus collectors (bounded labels)
internal/store/          PostgreSQL: pool, goose migrations, sqlc queries
internal/store/db/       code generated by sqlc (do not edit)
internal/store/storetest test helper: a fresh database per test
```

More packages arrive with each slice (see [PROGRESS.md](../PROGRESS.md)).

## Principles

- **One database, PostgreSQL only.** Postgres features (JSONB, `SKIP LOCKED`, `pg_trgm`) are used freely.
- **The spec is the contract.** Handlers implement the generated strict interface; the router never serves an undocumented endpoint under `/api/v1`.
- **Shared content, personal everything else.** Works, chapters and files are stored once; libraries, progress and settings are per user. Every handler checks what the caller may see.
- **Degrade, don't fail.** Only the database is required to be ready. When the metadata service or a plugin is down, the server says so and keeps serving what it can.
